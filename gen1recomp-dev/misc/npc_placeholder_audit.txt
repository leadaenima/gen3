NPC / object-event audit -- Ruby, generated 2026-09-02
======================================================================

SUMMARY

Ran every NPC's talk-script headlessly against the real extracted Ruby
ROM data (all 394 maps, 2268 object events, 1641 with a real script),
with all 8 badges / starter / Pokedex / a full-HM party set so flag-gated
content wouldn't look broken.

  - Scripted NPCs that produced NO text/effect: 0 / 1641
  - Scripted NPCs whose script threw a Lua error: 0 / 1641
  - Script opcodes used in Ruby data but NOT implemented by the
    interpreter: 1 (`setwarp`, 10 uses, all in LilycoveCity_ContestLobby
    -- a warp-target setter, not dialogue; doesn't affect text)

CONCLUSION: the Gen3 script interpreter is essentially complete for
Ruby. Every real ROM dialogue script already produces real text. The
"..." you've been seeing is NOT missing/unfinished dialogue -- it was a
bug in tryTalk's fallback (Game3.lua), now fixed: when an object event
has no script at all and isn't a special-cased type (nurse/mom/mart/
Birch/daycare/rival/etc), it now shows nothing, matching vanilla
exactly (field_control_avatar.c: a NULL script pointer makes A do
nothing in the real game -- no textbox, not even "...").

Cross-checked directly against the pokeruby decomp source: e.g.
PetalburgCity's Wally (OBJ_EVENT_GFX_WALLY, pre-cutscene) and every
`OBJ_EVENT_GFX_VAR_0` rival-cameo slot (Route119's is
FLAG_HIDE_RIVAL_ROUTE119) have `script = 0x0` in the ROM itself --
genuinely non-interactive by design, not a gap in this recomp.

The list below is every object event that has NO script and isn't one
of the special-cased NPC types. It is almost entirely this kind of
vanilla-faithful scenery/pre-scene actor (background decorations,
hidden-until-triggered rival/Wally cameos). It is included for
completeness / spot-checking, not because these need dialogue written.
If you find one in this list that a real player CAN walk up to and
which you know says something in the actual game, that specific one is
worth flagging -- but the audit above found zero evidence of that
happening anywhere in Ruby.
